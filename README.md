This project is a library management system created for my CS50x final submission. It provides a complete workflow for managing books, users, borrowing activity, financial records, and authentication. Each file in the project serves a specific purpose, and the system is designed to be simple, functional, and easy to maintain. The backend uses Flask, the frontend uses Jinja templates, and the database uses SQLite. The goal was to build a clear and practical application that demonstrates real-world web development concepts taught in CS50x.

The app.py file is the core of the entire system. It contains all routes, backend logic, session handling, and database interactions. Every action the user performs—logging in, registering, adding books, editing books, borrowing, returning, viewing history, and generating financial reports—passes through app.py. I chose to keep all logic inside one file because the project size is manageable and CS50x encourages clarity over unnecessary modularization. The file is organized into sections so that future expansion or splitting into multiple modules would be easy. The routing structure is straightforward, and each route corresponds directly to one of the templates, making the flow of the application easy to understand. The file also handles role-based permissions, ensuring that only admins can perform sensitive actions such as editing books or processing returns.

The add_books.html file is used to add new books to the system. It contains a form with fields for title, author, genre, stock, buy price, borrow fee, and status. I designed this template to be simple and efficient because adding books is a frequent administrative task. The form layout is minimal to reduce distractions and speed up data entry. The status dropdown allows administrators to control whether a book is active or suspended, which helps manage inventory without deleting items. The template extends layout.html to maintain consistent styling across the system.

The borrowed_books.html file displays all currently borrowed books. It shows the user, the book title, the borrow date, and the return date. If a book has not been returned, the template displays “Not returned” in red to make it visually clear. When the logged-in user is an admin, the template also shows a “Return” button for each unreturned book. This conditional logic ensures that only authorized users can perform return actions. The table layout makes the information easy to scan, and embedding the return form inside the table row reduces the number of steps required to complete the action.

The edit_book.html file allows administrators to modify an existing book’s information. It loads the current values into the form fields so the user can see the existing data before making changes. This design reduces mistakes and makes editing more intuitive. The template mirrors the structure of add_books.html but with pre-filled values. The status dropdown automatically selects the current status using Jinja conditions. The form posts to a route containing the book’s ID, which keeps the backend logic clean and predictable.

The finance.html file generates a financial report for the library. It includes filters for period (daily, monthly, all time) and transaction type (borrow or sell). The filters automatically submit the form when changed, making the interface responsive and reducing unnecessary clicks. The table displays each transaction with details such as user, book, transaction type, borrow date, return date, and amount. The amount is determined dynamically based on whether the transaction is a borrow or a sale. A “Total” value is displayed to summarize earnings clearly. This page helps administrators understand revenue patterns and make decisions about pricing or inventory.

The history.html file shows the complete borrowing history. It lists every borrow and return event, including those already completed. It uses a simple table layout similar to borrowed_books.html but without action buttons, because history is informational only. If a book has not been returned, the template displays “Not returned” in red to highlight incomplete transactions. This page is useful for auditing, tracking user behavior, and identifying frequently borrowed books.

The login.html file handles user authentication. It contains a simple form with username and password fields. I intentionally kept this page minimal because login should be fast and distraction-free. The template extends layout.html to maintain consistent styling, and the form posts to the login route. The centered box and clear labels make the interface easy to understand.

The register.html file allows administrators to create new user accounts. It includes fields for username and password. I designed this template to be nearly identical to login.html so users immediately understand how to interact with it. The form posts to the register route, and the layout keeps the interface clean and easy to use. This page is essential for adding new users to the system, especially in environments where multiple librarians or staff members need access.

The styles.css file defines the visual layout of the entire system. It controls spacing, colors, typography, and the appearance of forms and tables. I chose to write custom CSS instead of using a framework like Bootstrap because it keeps the project lightweight and demonstrates manual styling skills. The design focuses on clarity and readability rather than decoration. The CSS ensures that all templates share a consistent look, which improves usability and makes the system feel cohesive.

Each file in this project was designed with clarity, simplicity, and usability in mind. The templates focus on efficient workflows, the backend focuses on maintainability, and the CSS ensures a clean and consistent interface. Together, these components form a complete library management system that demonstrates practical application of CS50x concepts and provides a solid foundation for future enhancements.
